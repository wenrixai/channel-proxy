# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

OpenResty (nginx + Lua) reverse proxy that sits between Wenrix services and airline/aggregator channel APIs
(British Airways NDC, Travelfusion, Farelogix AA/LH/UA/EK). It holds the channel credentials so callers don't:
callers send requests with placeholders, the proxy injects real credentials, strips internal headers, and forwards.

No application code beyond `nginx.conf`, `start.sh`, `travelfusion.lua`. Python exists only for tests.

## Commands

```bash
./run_tests.sh                                              # build + run all tests via docker compose, then tear down
docker compose up --build --exit-code-from tests tests      # what CI runs
docker compose build && docker compose run --rm tests pytest -v tests/test_proxy.py::test_ba_request   # single test
pre-commit run --all-files                                  # ruff, isort, mypy, shellcheck, yamlfmt, actionlint, helmlint, helm-docs
helm lint deployment/helm/chart
```

Tests only run inside compose: the `tests` image copies `tests/` at build time (rebuild after edits), and needs
the `proxy` and `mockserver` (httpbin) services. Tests hit `/channel/<name>/anything`; httpbin echoes back the
request it received, so assertions check headers/body as seen by the upstream.

## Architecture

```
container start ─► start.sh
                    ├─ default + export every WP_* env var
                    ├─ write htpasswd / TLS cert files / tf_config.json
                    └─ envsubst nginx.conf.template ─► /etc/nginx/nginx.conf ─► exec nginx
request ─► location ~ ^/channel/<name>/(.*)
            ├─ proxy_set_header: drop x-wenrix-*, authorization, x-real-ip, x-forwarded-for; add channel API key
            ├─ access_by_lua_block: rewrite body placeholders with credentials
            └─ proxy_pass $WP_CHANNELS_<NAME>_PROXY_PASS/$1
```

- **`nginx.conf` is an envsubst template, not plain nginx config.** Every `$VAR` that is a valid shell name gets
  substituted at startup — unset ones become empty. Credentials are baked into Lua string literals this way. For a
  literal nginx variable (e.g. `$host`) write `${DOLLAR}host`. Regex captures like `$1` survive untouched.
- **Env vars must be exported in `start.sh`** or envsubst won't see them. Each channel follows the same pattern:
  `*_HOST`, `*_PROXY_PASS` (defaults to `WP_SERVER_PROXY_PASS`, else `https://<HOST>`), plus credentials.
- **Placeholders**: Farelogix bodies use `#FLX_USERNAME#`, `#FLX_PASSWORD#`, `#FLX_AGENT#`, `#FLX_AGENT_USER#`,
  `#FLX_AGENT_PASSWORD#`. Travelfusion XML uses `<LoginId>PLACEHOLDER</LoginId>`, `<XmlLoginId>PLACEHOLDER</XmlLoginId>`,
  `<CustomSupplierParameterList>PLACEHOLDER</CustomSupplierParameterList>`.
- **Farelogix accounts**: `WP_CHANNELS_FARELOGIX_<AIRLINE>_ACCOUNTS=cad,usd` adds `/channel/farelogix-<airline>/<account>/`
  locations with `WP_CHANNELS_FARELOGIX_<AIRLINE>_<ACCOUNT>_*` creds, rendered by `start.sh` from
  `farelogix_account.conf.template` into `/etc/nginx/includes/`. They're included via `$WP_SERVER_FILE_INCLUDES` above the
  legacy locations, so they match first; an account id must not equal the upstream's first path segment.
- **Travelfusion supplier params**: `WP_CHANNELS_TRAVELFUSION_SUPPLIER_PARAMETERS` (JSON, shape in `tf_config.json`)
  is written to `/tf_config.json` at startup and looked up per request by `x-wenrix-iata-number` + `x-wenrix-supplier`
  headers via `travelfusion.lua`. Required when `WP_CHANNELS_TRAVELFUSION_LOGIN_ID` is set.
- Server-level: `WP_SERVER_PORT` (8080), `WP_SERVER_RESOLVER`, `WP_SERVER_DEBUG` (prints rendered config),
  `WP_SERVER_HTTP_USER/PASS` (basic auth), `WP_SERVER_TLS_*` (base64 cert/key), `WP_SERVER_PATH_INCLUDES`
  (comma-separated nginx include files). `/` is the health check, `/metrics` is `stub_status`.

## Adding a channel

Follow commit `6294239` (Farelogix EK). Touch all of:
1. `nginx.conf` — new `location` block (copy closest existing channel).
2. `start.sh` — export `WP_CHANNELS_<NAME>_*` with defaults (new FLX airline: also add to `FARELOGIX_AIRLINES`).
3. `docker-compose.yml` — point `*_HOST`/`*_PROXY_PASS` at `mockserver`, set test credentials.
4. `tests/test_proxy.py` — header stripping + placeholder substitution test.
5. `deployment/helm/chart/values.yaml` — commented env example.

## Release

Push to `main` → CI computes CalVer (`YYYY.MM.N`), pushes multi-arch image to Docker Hub + ECR Public, packages the
Helm chart with that version, creates a GitHub release. Don't hand-bump `Chart.yaml` version; CI overwrites it.
`deployment/helm/chart/README.md` is generated by helm-docs from `values.yaml` comments. `build.sh` is a legacy
manual build.
